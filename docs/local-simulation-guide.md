# Local Simulation Guide

How to run and interpret the BuildVault local demonstration and test suite.

**Read this first:** nothing in this directory is the UGREEN runtime. No UGREEN expert
agent has executed, no `cli.invoke` has run, and no file has been written to a UGREEN
NAS. The simulation exists so the BuildVault workflow can be *seen* and *tested* on real
inputs before NAS access is available.

## 1. Requirements

- Node.js (any recent LTS). No npm packages are installed or required.
- Python 3 (only for the optional PDF and ZIP helpers; the simulation itself is pure Node).
- A browser for the dashboard.

## 2. Commands

Run from the repository root.

```bash
# 1. Deterministic Stage 4 fixture and Skill integrity tests (must stay at 29/29)
node tests/run-tests.mjs

# 2. Stage 7 orchestration and simulation tests (31 checks)
node tests/sim/run-tests.mjs        # (file: tests/sim/run-sim-tests.mjs)
node tests/sim/run-sim-tests.mjs

# 3. Regenerate the report, handoff brief and JSON artifact
node tests/sim/generate-demo-artifacts.mjs

# 4. Official UGREEN checkers (toolkit 0.7.3)
node toolkit-0.7.3/uliya-skill-kit/scripts/check-skill.mjs buildvault-skill/buildvault-project-intelligence
node toolkit-0.7.3/uliya-skill-kit/scripts/check-skill.mjs buildvault-skill-dev/buildvault-project-intelligence
```

To view the dashboard, open `demo/buildvault-simulation-dashboard.html` in a browser.

## 3. What each part does

| Path | Role |
|---|---|
| `tests/sim/simulate.mjs` | The simulation engine. Reads the synthetic fixtures, derives inventory, evidence ledger, timeline, milestones, scope findings, readiness, recommendations, registers, BOM rollup. |
| `tests/sim/mock-experts.mjs` | Simulated expert responses and the verbatim quotes the harness verifies against fixture text. |
| `tests/sim/run-sim-tests.mjs` | 31 checks: 10 orchestration (`ORCH-*`) and 21 simulation (`SIM-*`). |
| `tests/sim/generate-demo-artifacts.mjs` | Writes `engineering-report.md`, `handoff-brief.md` and `simulation-result.json`. |
| `tests/sim/output/` | Generated artifacts. Safe to delete; regenerated by the command above. |
| `demo/buildvault-simulation-dashboard.html` | Self-contained dashboard. The data is embedded at build time, so it needs no server. |
| `buildvault-skill-dev/` | The development Skill candidate. The Stage 5 Skill is a separate, untouched directory. |

## 4. What is real and what is simulated

| Output | Source | Status |
|---|---|---|
| File inventory, hashes, sizes | Read directly from the synthetic fixture files | **Real fixture data** |
| Timeline dates, milestone evidence, conflicts, BOM values | Derived from fixture text | **Derived from real fixture text** |
| Simulated expert responses (`mock-experts.mjs`) | Hand-authored test doubles | **Simulated** — never presented as expert results |
| The HTML dashboard | Generated from the simulation output | **Simulated** |
| The report and handoff brief | Generated from the simulation output | **Simulated** |
| Any NAS operation | Does not exist in this environment | **Not performed** |

Every simulated fact carries a verbatim quote that the harness checks against the fixture
file, so the simulation cannot drift from the evidence. The check `SIM-01` fails the whole
suite if any quote stops matching.

## 5. Interpreting the test results

Two suites, and they mean different things:

- `tests/run-tests.mjs` (29 checks) — **fixture integrity and static Skill structure**.
  These really ran. They prove the fixtures contain the conditions each test needs and
  that the Skill's instructions are structurally correct against the real catalog.
- `tests/sim/run-sim-tests.mjs` (31 checks) — **the specified logic, executed locally.**
  These really ran. They prove that the decision rules the Skill specifies (status
  handling, approval scoping, conflict preservation, ambiguous-date handling) behave as
  specified, using simulated delegation input.

Neither suite proves NAS runtime behaviour. `ORCH-01` passing means the *specified rule*
for `completed` behaves correctly in this harness, not that any expert returned
`completed`.

## 6. Updating the simulation

- To change a simulated expert response, edit `tests/sim/mock-experts.mjs`. Keep every
  `sourceQuote` verbatim from the fixture, or `SIM-01` will fail.
- To change a fixture, edit `tests/fixtures/buildvault-synthetic-project/`, then run
  `node tests/run-tests.mjs --update-manifest` to re-baseline, and re-check the quotes.
- After editing the simulation, re-run the artifacts generator so the dashboard data is
  current, and re-embed it into the HTML (the generator writes `simulation-result.json`;
  the dashboard reads the embedded copy).

## 7. Environment note

Development was performed in OpenCode, which is **not** one of the assistants the UGREEN
Starter Kit lists (WorkBuddy, Claude, Codex). Nothing here has been validated inside an
officially supported assistant, and nothing here has been validated on a device.
